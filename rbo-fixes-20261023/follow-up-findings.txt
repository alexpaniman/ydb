F01 — Repeated DISTINCT aliases produce duplicate input definitions

Correctness: selecting one input column under multiple DISTINCT result aliases
can fail during new-RBO import with “Duplicate Map output”. This also affects
ordinary integer inputs, so it is independent of C23's bare-Null hash-key bug.
The legacy planner passes the isolated control. Failed C23 alias records remain
preserved; they were not reclassified as passing C23 tests.

Cause: ProcessAggregations adds a direct input definition once per DISTINCT
result alias. BuildAggregationPipeline emits those definitions into a projecting
Map with repeated names. The importer correctly rejects duplicate definitions
within that Map. This failure is not evidence that inherited Map bindings must
be overwritten, and the fix does not weaken importer collision checks.

Proposed narrow fix: share an existing identical direct-row input definition
while retaining every DISTINCT result trait and alias. Computed expressions,
nested member access and changed optionality are not merged merely because
their names coincide. The patch has its own pinned-main base, separate from C23.
