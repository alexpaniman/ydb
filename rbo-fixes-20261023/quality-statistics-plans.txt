Q08 — Apply a filter's local selectivity once.
Confirmed: kqp_rbo_compute_statistics.cpp:389-408 copies input ERows/EBytes, computes local predicate selectivity, then scales the copied values by local * accumulated selectivity. Previously applied reductions are multiplied again. PartiallyPushedDown exits before this path.
Narrow change: scale ERows and EBytes by local selectivity only; update Selectivity by accumulated * local. Keep PartiallyPushedDown handling unchanged. Do not alter read predicate costing in the same commit without establishing a separate repeated reduction there: the source initializes its own estimates before applying OriginalPredicate.
Verification: construct statistics-bearing operator chains with surviving filter boundaries and nonunit input Selectivity; assert row/byte ratio follows only each new local factor. Controls: first filter, identity selectivity, empty estimate, PartiallyPushedDown. Generated SQL plan check must establish the boundaries survive simplification; otherwise use an operator-level generator. No exact latency improvement asserted.

Q09 — Give a real scalar aggregate exact output cardinality.
Confirmed: kqp_rbo_compute_statistics.cpp:571-590 copies ERows and cost and changes only bytes per column count. Metadata already distinguishes keyless output as One at :492, but the numeric statistics ignore it.
Narrow eligibility: keyless, not IsDeduplication(), and phase Undefined (logical unsplit) or Final. Do not label Intermediate per-task output globally one; do not label keyless DISTINCT/dedup globally one on empty input. Grouped cardinality estimation remains separate work.
Set ERows=1, estimate EBytes from output row width (input average width scaled by output width when the input estimate is positive), and use a finite nonzero-width fallback for empty-input statistics. Preserve the input processing cost: producing one row does not make scanning/aggregation free. Avoid division by zero for input row/column counts. Selectivity bookkeeping must not reintroduce input cardinality through later filter costing.
Verification: empty and nonempty scalar aggregates, wide/narrow output, a downstream join, grouped aggregate and Intermediate/dedup controls. Assert finite bytes and exact scalar row estimate; semantic outputs remain equal to baseline controls.

Q19 — Separate partial statistics data from diagnostics.
Confirmed: response merge preserves only the first response's Issues, and ApplyColumnStatistics discards all merged fields whenever that first response has any issue. Ordering of request kinds therefore determines which successful data and diagnostics survive. Future exceptions currently rethrow and are a separate failure path.
Narrow change: append later response Issues through AddIssues, merge available data regardless of which request failed, and log aggregated diagnostics without putting data application behind an else branch. Do not discard successful fields simply because another response has an error. Leave fatal future-exception policy unchanged in the minimal commit, or explicitly convert individual request failures to diagnostics with tests rather than swallowing all exceptions.
Critical guard: do not gate payloads on TOperationResult::Success() as-is. Its default status is DEFAULT_ERROR, while successful DispatchStatRequests callbacks construct TColumnStatisticsResponse with data and never call SetSuccess(). Presence of returned fields and absence/presence of Issues are the current usable contracts; normalizing that status would be an additional explicit change.
Independent Q19 branch should demonstrate success applied to an initially uncached table; Q18 is separately required when the table entry already exists. Tests permute failure/success order, all-success and all-failure responses, and verify both field-presence and diagnostic counts. An operator/helper-level mock is more precise than SQL-native data-service fault injection.

Q20 — Include both join inputs when matching hints.
Confirmed: ComputeAlisesForJoin at kqp_rbo_compute_statistics.cpp:27-31 clears rightAliases and uses leftAliases as the result union. Both metadata (:618) and statistics (:716) call it. Right-side ApplyRowsHints/ApplyBytesHints receive an empty list; result hint matching uses a left-only relation set.
Narrow change: accept both input operators, collect left/right relation sets, and compute a union from both HintRelations before deriving result aliases. Update both callers. Deduplicate relation instances/labels consistently with TColumnLineage::GetAliases.
Guard: simply concatenating alias strings can collapse a self-join. GetAliases creates suffixes based on distinct relation IDs within its supplied set; use merged relation identities for the result union and verify duplicate aliases/self-joins. The join's output HintRelations is unsuitable for the union at this point: it may not yet exist in ComputeMetadata and deliberately omits non-output sides of semi/anti joins. Hint semantics for the joined relation still involve both inputs.
Verification: left-only, right-only, composite and absent row/byte hints; join nesting; self-join relation IDs; semi/anti joins. Assert the intended hint is consumed once and unrelated hints do not change the larger result estimate. Semantic results should remain equal; algorithm changes are expected but are not proof of speedup.

Q25 — Preserve push intent without authorizing unrelated expressions.
Confirmed: rules/push_map_elements_through_input.cpp:78-100 moves definitions into the lower Map without carrying top.NeedToPush. Through-input QuickMatch at :103 requires NeedToPush. A newly reconstructed kept top Map also defaults the flag to false, so partially retained definitions can lose intent too.
Do not blindly OR the map flags as the final fix. When lower.NeedToPush was false, that can make all preexisting lower expressions eligible for movement through Filter/Join, including expressions whose evaluation placement matters. The current rule rechecks column dependencies and preserved join sides, but those checks are not an effect/exception-demand proof.
Preferred bounded design: retain push intent per definition (or maintain separate Map groups for movable versus placement-bound definitions), have fusion preserve it, and let through-input pushdown consult it. Carry intent through CopyImpl, rename/rebind and partial reconstruction. An alternative narrow patch must prove every newly eligible preexisting definition is safe before combining flags, and keep separate groups otherwise. This is larger than the other quality fixes and should follow correctness repairs, especially C15.
Verification: flagged top over unflagged bottom, reversed flags, partially dependent definitions, all-moved/none-moved cases, copies and computations, outer joins, an expression that errors on filtered-out rows, and branch-demanded scalar cardinality checks. Both movement counts and semantic outcomes are required. No source edits proposed during freeze.
