F03 — Physical-window interval SUM uses an unsuitable accumulator

Correctness: new-RBO physical windows accumulate Interval and Interval64 SUM
in the public result type instead of the Decimal state used by established SUM
traits. Interval64 addition lacks the required aggregate runtime implementation;
small Interval intermediate sums can lose a value when the interval range is
exceeded, even if later values would bring the frame total back into range.
Native confirmation of the physical-window cases remains pending; F02's native
aggregate failure is related source evidence, not a substitute for that check.

Narrow fix: convert interval inputs through Int64 into Decimal(35,0), retain that
state while updating a frame, and convert the final result back through Int64 to
the original interval type. Final overflow remains NULL. The shared window
accumulator/result helpers cover running, finite, incremental, suffix and peer
paths. No yql/essentials code changes. Whole-partition windows rewritten into
logical aggregates use the separate F02 fix.
