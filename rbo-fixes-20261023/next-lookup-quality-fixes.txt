Read-only implementation plans for lookup/access quality issues
Reviewed against pinned main e8700d379b3b9c4fbaf68f36424e6bcf08314fd2 and current independent C47 diff. No production changes, builds, native executions, performance measurements or rendered query inputs were made for these plans. Correctness remains the acceptance gate. All paths below are under ydb/core/kqp/opt/rbo unless stated otherwise.

Q03: uncovered residual prevents selective noncovering index access
Functions: rules/push_ranges.cpp TPushRangesRule::SimpleMatchAndApply, the noncovering index evaluable test and lookup construction.
Narrow first implementation: allow a noncovering candidate with useful extracted ranges even when the residual needs base-row columns. Read the full base primary key from the index, construct TOpTableLookup, then evaluate the complete PrunedLambda on the fetched base-row outputs using the original IU bindings. This first version need not split/reorder residual conjuncts: leaving the entire residual after lookup preserves its evaluation order and still recovers the selective access path. Keep the original predicate for subsequent lookup rewrites; keep all residual columns live in main lookup outputs. Do not rewrite a limited read so filtering changes its selected input. Reuse the existing candidate scorer and full-PK construction (including C49 correction).
Extension only if measured useful: partition repeatable, effect-safe conjuncts between index and fetched rows, with a residual guarantee and order proof. Do not move a throwing conjunct past a guard merely because its fields happen to be covered.
Plan acceptance: selective index range followed by main-table lookup followed by residual; original full base scan absent in the selective fixture. Index payload includes full PK but excludes uncovered payload. Compare successful result hashes including nullable keys and empty matches, then measure candidate rows and base rows fetched. An unselective or keyless index must not displace a cheaper base scan. The new outer Filter(TableLookup) shape currently falls outside MatchLookupJoinRightSide, so retain that conservative behavior or extend its matcher deliberately with proven predicate provenance; do not silently discard the new residual.

Q04: unfiltered bounded sort misses a matching secondary index
Functions: new narrow order-aware access rule in the existing Index selection rules stage, TOpSort::IsTopSort/GetSortElements, rules/propagate_topsort_through_stage.cpp CanPushSortToRowRead; reuse BuildTableCallable and ordinary-index kind validation.
Match a bounded sort directly over a row read (optionally through proven direct-copy projections). Enumerate ready synchronous implementation tables even without Filter. Require every live output to be covered by implementation metadata, the sort keys to match a physical key prefix with compatible direction/null placement, and no existing restrictive ranges/limit/ForcePrimary/tablet selector. Rebuild the read with the selected table while preserving IDs, source settings and aliases. Keep the sort operator: the existing physical pushdown can install sorting/limit while preserving global ordering. Initial implementation can restrict to covering indexes rather than duplicating noncovering ordered-lookup machinery.
Plan acceptance: matching covering index read has sorted direction and bounded ItemsLimit; base-table full scan disappears; final ordering and limit remain correct. Controls: no matching index, noncovering index, mixed directions, nullable-key placement mismatch, disabled automatic selection, unsupported index family, existing limit, unbounded sort. Measure scanned rows/bytes and sort input rows; do not claim runtime improvement from table-path change alone. Coordinate with Q05 null-order fix.

Q06: secondary prefix wins before complete primary-key probe is considered
Function: kqp_rbo_lookup_join.cpp ChooseLookupJoinTarget; current no-range early return from TryToFindBestIndexForRightSide precedes consider(main table).
Compare base and index candidates before returning. A narrow independent fix can first protect a complete base physical-key probe against a partial secondary prefix. A fuller shared scorer should prioritize proven per-probe row bounds (complete physical key and point-count bound), then covering cost, then useful prefix length, then deterministic tie order. Do not assume declared unique-index null semantics; completeness of the implementation table's physical key supplies the safe bound. Do not call a multi-point prefix a single-row access. Both CBO and physical rewrite already call ChooseLookupJoinTarget, so preserve that common decision.
Plan acceptance: with complete base PK bound and a longer-looking but incomplete secondary key prefix, both CBO and physical plan select the base point lookup; candidate row upper bound is one per input key. Partial-PK control may still choose a selective covering index. Check point-prefix cardinality, composite/nullable PK and no-statistics cases. Measure lookup fan-out and rows read. Independent Q06 must not accidentally depend on Q17 coverage repair.

Q07: costing and executable lookup eligibility disagree
Functions: kqp_rbo_cbo.cpp IsLookupJoinApplicable/IsLookupJoinApplicableDetailed; rules/rewrite_join_to_index_lookup_join.cpp SimpleMatchAndApply, BuildFetchedRowFilter, MatchKeyPrefix and KeyTypesMatch; kqp_rbo_lookup_join.h/.cpp for shared helpers.
Create a shared, side-effect-free eligibility/target description that checks the feature/query gates, supported join kind, shared-producer boundaries, null-safe key policy, nonempty key prefix, actual optional-stripped key compatibility, recoverability of range predicates, residual/filter dependencies and imported storage restrictions. Validate before accepting ChooseLookupJoinTarget. Current Detailed returns true immediately when target exists, bypassing even its local fetched-filter checks. The two BuildFetchedRowFilter implementations should become one shared helper. Include C47 imported settings in this contract.
CBO must receive the actual types of its key IDs, not infer them from source column labels or lineage alone. TRBORelOptimizerNode already retains the typed boundary Op; a provider map of boundary IU to annotated type (built when packing the island) can service left keys from composite CBO trees. Handle outer-join optionality consistently with the execution contract. Apply shared checks before costing. Remove the late forced MapJoin for a type mismatch once CBO cannot pick that candidate; if a post-CBO transformation changes eligibility, select/re-cost a safe fallback explicitly rather than inheriting lookup costs or broadcasting unbounded data. Forced invalid hints need a defined rejection/fallback contract.
Plan acceptance matrix: enabled/disabled lookup, supported/unsupported query kind, exact/mixed scalar types, optional-compatible keys, null-safe keys, shared input, range with/without recoverable predicate, imported read settings, supported/unsupported index kind and a large right side. Every costed lookup must become a physical lookup with the same target and key prefix. An ineligible case must use the normally costed hash strategy; no late uncosted MapJoin. Preserve C30/C45/C47 guards. This is larger than a one-line type gate but should remain a focused shared-contract refactor.

Q17: implicit primary keys omitted from covering-index test
Functions: kqp_rbo_lookup_join.cpp TryToFindBestIndexForRightSide and IsCoveringIndex.
After validating the index as an ordinary ready synchronous index, fetch its implementation metadata and test requested columns against impl.Columns using the existing IsCoveringTable helper. Use implementation physical KeyColumnNames when computing bound prefix rather than treating the declared keys as the whole storage key. Do not broaden eligibility of specialized indexes just because their metadata exposes fields. Reuse the C30 whitelist on integration; an independent base branch must contain the same narrow kind guard if required for safe use of implementation metadata.
Plan acceptance: a lookup producing an implicit base-PK field plus a declared covered field chooses the covering implementation table and needs no main-table lookup. Explicitly missing payload remains noncovering. Include composite PK, index whose declared key overlaps the PK, ready/not-ready state, async/specialized exclusions and projection-order controls. Measure selected path and fetched columns. Source review confirms this mechanism, not a measured latency change.

Q23: original equality keys remain in postlookup payload
Functions: analysis/logical_liveness.cpp TOpIndexLookupJoin::PropagateLiveness; TOpTableLookup::PropagateLiveness; physical_conversion/kqp_rbo_physical_lookup_join_builder.cpp BuildLookupInput and ProcessFetchedRows; optional focused pruning before AssignStages.
Stop treating TOpIndexLookupJoin.JoinKeys (retained for display/provenance) as runtime consumers. Propagate downstream demand plus actual residual/fetched-filter dependencies instead. Probe keys remain live on the input edge through TOpTableLookup.LookupKeys and Prefix.Equalities, so narrowing happens after key construction. ResidualJoinKeys.Left and filter input requirements are already retained at TableLookup; ensure residual right keys and fetched-row filter fields remain in fetched payload too.
For complete right-payload pruning, add a focused TOpTableLookup::PruneOutputs that keeps downstream fetched fields, ResidualJoinKeys.Right and FetchedRowFilter dependencies; call before stage assignment after lookup representation is created. A general late pruning stage needs special attention to tuple-producing lookups and chained noncovering lookups. Do not remove the intermediate PK required by the second lookup. The smaller liveness-only change already removes unused wide left probe fields from fan-out payload, but should not be reported as full right-payload pruning.
Plan acceptance: unused wide equality key exists in probe-key structure but not carried left payload; no dead fetched prefix key beyond lookup. Add controls where that same field is selected, participates in residual equality, is used by fetched filtering, is a point-prefix equality, or feeds a nullable/nonnullable two-step index lookup. Compare left/inner/semi/anti multiplicities and output nullability, then measure payload field count and bytes after lookup. No speedup claim without measurement.

Q24: proven range predicate retains payload fields for provenance
Functions: TOpRead::GetRequiredColumns/PruneOutputs, physical_conversion/kqp_rbo_physical_source_builder.cpp BuildPhysicalOp, physical conversion GetLiveOutputIUs, and phase ordering in TKqpNewRBOTransformer.
Preferred narrow boundary: after lookup rewriting is finished, project row-source storage outputs using actual live output IUs. Exclude OriginalPredicate-only dependencies at physical export; preserve logical provenance for statistics/explain and any embedded semantic program dependencies. Row source rename/output schema must use exactly the selected storage fields. OriginalPredicate is not a runtime row program after storage ranges enforce it. Residual filter fields remain live through the filter consumer. Explicitly validate empty-payload/count reads.
Alternative logical cleanup: clear provenance after Physical rewrites II, then global prune before AssignStages, but this requires retaining source selectivity/explain data separately. Simply resetting OriginalPredicate loses final statistics because Optimize recomputes RequireStatistics after all stages; retaining it with pruned argument types also fails its annotation contract. Therefore do not implement a blind reset or remove GetRequiredColumns protection before lookup rewrites. OLAP needs separate program-dependency handling; limit the first physical-export change to row storage if that makes the contract precise.
Plan acceptance: storage source no longer projects a wide key used solely to compute/enforce a range; bounds remain present, result hashes match, and source selectivity/explain does not silently disappear. Controls: uncovered residual, lookup rewrite needing original predicate, selected key, embedded OLAP expression, and zero-column count. Measure read projection width and returned source bytes, not just logical Columns_.

Q29: reconstructed fetched filter repeats deterministic residuals
Functions: duplicate BuildFetchedRowFilter in CBO and lookup rewrite; TExpression::SplitConjunct and equality helper in kqp_expression.cpp.
Share the filter-combination helper, preserve original conjunct order, and append only residual conjuncts not already represented by an equivalent existing deterministic/total expression with the same IU binding and type. Use the existing expression equality machinery rather than text/display-name comparison. Avoid deduplicating volatile calls or potentially effectful checks merely because their syntax is equal. A provenance mapping from the extractor's residual to original conjuncts is safer than dropping the entire residual: later rules can introduce new filters. This helper should remain behaviorally identical in CBO and physical rewrite; Q07 can supply the common entry point.
Plan acceptance: after focused lowering, a repeated safe comparison appears once in fetched-row filtering; an independently introduced predicate still appears. Controls: duplicate spellings with different source IDs, different types, repeated volatile/UDF/Ensure-containing expressions, guarded predicates, NULL booleans and distinct conjunct order. Count actual physical evaluations/IR occurrences after peephole; retain the finding as construction-only if peephole already eliminates them. No unsupported runtime multiplier claim.

Suggested order after correctness gates: Q17, Q06, Q29, Q03, Q04, Q23, Q24, Q07. Q07 can move earlier if the shared eligibility contract is needed to prevent unreliable plan comparisons. Keep independent branches from pinned main; resolve common-helper integration explicitly rather than stacking fixes. All plan checks should store normalized operator/settings counts and hashes, never rendered inputs or full query-bearing traces.
