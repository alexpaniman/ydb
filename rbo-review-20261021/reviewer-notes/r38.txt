R38: Cross-object state, rebinding, and cached analysis invariants

Scope: kqp_plan_props.{h,cpp}, kqp_rbo_context.{h,cpp}, rebind_consumers.cpp, logical_renames.cpp, expression caches/ownership, parent traversal, rewrite boundary invalidation. Two source passes: first API contracts and mutation paths, then actual pipeline ordering and consumer/capture reachability. No native runs, repository modifications, or reproduction inputs.

Correctness: no additional independently verified SQL-result bug in this slice.

Existing candidate independently supported, but not promoted to a confirmed SQL bug:
- DependentJoin parameter identity can be changed without rebinding its body's captures. logical_renames.cpp:128-134 substitutes Dependencies and the keys as well as values of DomainColumns. The intended distinction is documented at kqp_operator.h:1126-1128: parameters are stable identities, while domain columns carry their values. RebindConsumers at rebind_consumers.cpp:139 only calls RenameUsedIUs on ancestors; it does not traverse the sibling/body subtree to rewrite AddDependencies. Consequently a domain-side replacement whose source is also a parameter can leave the body's capture.Outer referring to the old parameter while the dependent join now lists its replacement. dependent_join_pushdown.cpp:313 then cannot match that capture to the join's Dependencies. This is the same candidate previously found by R15, not a new count. Source reachability requires a nested dependent join whose domain is rewritten during decorrelation; no native confirmation was performed. Correction direction: preserve parameter identities when only a domain input binding changes, recording parameter-to-new-column in DomainColumns; if intentionally changing a parameter identity, rebind the entire body's capture boundary as a coordinated operation.

Supporting check on existing C06:
- kqp_operator.cpp:612-623 intentionally preserves capture.Type when changing its outer binding. That is valid only for type-preserving replacements. The domain-elimination rule at dependent_join_pushdown.cpp:421 substitutes an inner equality operand directly, so its already-reported differing-type bug also violates this capture contract. Do not add a separate type-cache defect: fix the replacement rule to maintain the value/type contract.

Diagnostic correctness, separate from query correctness and optimization quality:
- Mixed Boolean nesting is rendered ambiguously in simplified explain. kqp_expression.cpp:281-299 FormatSimpleLogic recursively renders child expressions but joins their text without preserving parentheses. FormatSimpleBinary at 260-279 does apply NeedParens, whereas the logic formatter does not. An OR child of AND is therefore printed with the ordinary SQL precedence of a different condition. This affects explanations used to inspect optimizer decisions; it does not change the executed AST. Correction: render parentheses for Boolean children where precedence or non-associativity requires them (including XOR), or parenthesize every nested mixed Boolean operator. Static source confirmation only; no native diagnostic test.

Optimization quality:
- No new independent quality issue beyond the already-covered whole-plan property recomputation after each rule and local alias handling. RebindConsumers invalidates all ancestors, including those above defining boundaries; this is conservative and correct. Optimizing that invalidation requires a separate dependency-aware design and should not be weakened as a correctness fix.

Checks that did not produce a finding:
- Subplan entries are individually allocated, so insertion/removal of unrelated entries preserves borrowed plan slots. Registry binding IDs remain stable while result and parameter bindings have separate APIs.
- Raw expression dependencies are cached by Node identity; resolved dependency sets refresh against the current subplan registry every call. Current call sites copy resolved results or consume them before another call; no retained scratch-buffer alias was found.
- Row references are recognized by argument identity. Internal construction protects nested lambda locals; FromExpr expands whole-row uses into source-shape members. Rename operations use simultaneous substitutions and preserve ordered positions/directions/external names.
- RebindConsumers snapshots the upward closure, counts reconvergent edges, waits for all affected inputs, and invalidates ancestors even across defining boundaries. Its grouping-set/union/replicate distinctions agree with the operators' output contracts. DistinctAll is a defining boundary, unlike ordinary aggregate grouping keys.
- Parent rebuilding uses one postorder visit per active operator, so every child's links are cleared before all parent edges are appended. The shared Replicate hub's owning producer slot remains canonical. The type pass independently rejects unsupported ordinary shared operators.
- Read OriginalPredicate is not exposed by GetExpressions, but conversion creates reads without this field; rules install it after the root owns PlanProps, and logical copying rejects reads with embedded programs/predicates. No current dangling PlanProps path was established from the missing override.
- TRBOContext owns no detached expression/operator graph and borrows contexts with an enclosing optimization lifetime. No independent dangling-context issue was found.
- RebindResults updates producer result IDs without renaming call IDs. Nested external dependencies are normalized into caller-local captures by BindSubplanCaptures before later rules, so RefreshDependencies need not recursively collect callee outer IDs.
