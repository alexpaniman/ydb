C49: NEW CORRECTNESS FINDING, SOURCE-COMPLETE AND NATIVE-CONFIRMED FOR LEFT JOIN

P1: Noncovering index reads can advertise an incomplete primary key as unique, making late outer-join filter inlining mix different left rows.
Primary defect: ydb/core/kqp/opt/rbo/kqp_rbo_compute_statistics.cpp:225-231.
TOpTableLookup::ComputeMetadata appends each primary-key column that happens to be present in the fetched output. It does not require the complete composite key. In contrast, ordinary source metadata at :275 uses ResolveStorageColumns (:85-95), which correctly abandons uniqueness if any component is absent.
Reachable producer: rules/push_ranges.cpp:690-691 creates a nonjoin TableLookup for a noncovering secondary-index read using read->GetColumns(). The preceding Pruning I stage can already have removed unused primary-key components; EnablePruneKeyColumns defaults true (table_service_config.proto:603). The index's internal lookup keys still contain the complete primary key, but those are input keys and do not establish uniqueness of the projected fetched output.
Wrong-results consumer: rules/inline_join_filters.cpp:109-130 trusts Metadata.KeyColumns as left-row identity when reattaching filtered inner matches to the original left relation. This stage runs after index selection (kqp_rbo_transformer.cpp:720 and :743-749). A retained nonnull component passes CheckNonNullKeys even when other composite components were discarded. Distinct left rows sharing that component can therefore borrow one another's matches. Root observed LEFT row multiplication and a failed semantic oracle, while retaining the full key made the control pass. Legacy rejected this tested shape, so this is a new-RBO wrong-result finding against relational semantics, not a demonstrated legacy regression. LeftSemi and LeftOnly have the same unsafe source transformation, but both optimizer modes rejected the generated variants; no native wrong-result claim is made for those variants.
Applicability: noncovering ordinary secondary-index read on the left, partial composite key retained, residual join predicate requiring inlining, and channel spilling enabled so the newly introduced Replicate can execute. CBO is not needed for the defect. Force-inlining or disabled block joins makes the consumer deterministic. Complete-key output is a control. If the partial key is nullable the existing nullability assertion masks this wrong-results path.
Correction: use the same all-or-none storage-key resolver for nonjoin TableLookup metadata. Preserve complete unique identity when late join-filter reconstruction needs it, or reject/use a fresh row identity instead of silently treating a projection as unique. The primary invariant is that a proper subset of a unique key must never be advertised as unique without a separate proof.
Verification: two source passes traced producer pruning, metadata construction, pipeline order, map propagation, nullability guard and consumer behavior. An abstract generated identity model checked 5,456 states; counts of states with changed semantics were Left 3,990, Semi 4,980, Anti 4,980. These are model checks, not engine executions. No generated witness is saved.
Artifacts: r42_partial_identity_model.py retains the abstract generator; partial_lookup_key_generator.py retains a compositional native generator with semantic oracle and full-key control. Both retain no generated inputs. Root executed the native generator separately and confirmed the LEFT partial-key failure and full-key control. Root removed the per-seed YqlSelect setting because it independently interfered with setup translation on the RBO-enabled server; plain seeds worked.

INDEPENDENT CONFIRMATIONS AND CHALLENGES

- C39 residual ON predicate loss has a complete producer-to-consumer source chain. The global block flag is consulted before actual Full/complex-key block capability is known, and scalar Grace consumes no residual predicate. No later corrective filter was found. Unsupported Full Map is a separate rejection path and must not mask the Grace case.
- C37 stale window partition metadata and C38 one-sided Full join partition metadata remain valid. Stage assignment actually changes window partitioning while generic unary metadata copies the previous partitioning. Full unmatched right rows have NULL left keys without being consolidated by those keys. Later aggregate shuffle elimination consumes those properties.
- C34 tuple aggregate state confusion and C35 interval AVG type mismatch remain supported. The scalar empty-input wrapper classifies tuple result types by shape rather than aggregate identity; the AVG nondecimal accumulator is explicitly Double. The ordinary two-stage AVG logical type is intentionally not its physical tuple state, so an ordinary decimal AVG failure must not be inferred from that difference alone.
- C41 effect/result root classification is corroborated: global WithEffects removes all transaction and query result bindings. This should be described as the native-observed task-construction failure, not as silent result omission without further evidence.
- C42 union branch normalization is consistent with conversion behavior; physical union performs field renaming and cannot repair absent widening casts on a nested-union edge.

This alone does not establish a new supported-query ordering regression. Existing DESC primary-key top-N missed pushdown remains optimization quality.

- Aggregate grouping-key/aggregate-input overlap is handled by separate input/state names and positional extractor mapping; no extra binding defect found.
- Shared producers are separated by Replicate ports; unary map/filter operators get consumer stages, while pushed aggregate branch transformations retain their output index. No additional cross-branch mutation defect found.

- Type-annotation retry and focused compatibility gaps were already reported and remain source-only candidates where native reachability is absent; not double-counted.

THIRD NARROW PASS AND BOUNDED CONVERGENCE

A third source pass traced every new-RBO Metadata.KeyColumns consumer that can run after range/index selection, together with every TOpTableLookup construction site. It produced no additional distinct source-complete correctness finding beyond C49.

- The only nonjoin TableLookup producer is noncovering range-index selection; every lookup constructed by the join rewrite has a join kind, and its metadata explicitly clears unique keys. Therefore the partial-key defect should be fixed at the nonjoin metadata producer, not generalized to every lookup join.
- Ordinary Read metadata resolves the complete physical primary-key tuple or returns no key; Replicate rebinding also clears an incompletely available key. Neither repeats the subset promotion found in TableLookup.
- The late filter reconstruction is the demonstrated destructive consumer. Left-join elimination runs before range selection in this pipeline, so C49 must not also be reported as a native-observed postlookup elimination failure.
- CBO receives projected key facts for costing and ordering construction. That can extend C49's bad metadata influence, but no separate source-complete wrong-result algorithm choice was established from those consumers. Existing lookup eligibility/lowering gaps remain separately tracked.
- Aggregation metadata can retain an input key when it is a subset of grouping keys. If that input key was already falsely shortened by C49, aggregation can propagate the false uniqueness claim; grouping guarantees only the complete grouping tuple. This is another propagation route for the same TableLookup producer defect, not a new independent bug count. Fixing the originating metadata removes that false premise.
- Map metadata passes through complete rows and Replicate ports preserve/rebind available identities. No additional partial-key creation was found there.
- Covered ordinary secondary indexes use their implementation-table primary key through the ordinary Read metadata path. Specialized-index row multiplicity and write-maintenance failures are already separately owned and are not additional findings from this sweep.

Disposition: one new distinct physical correctness issue found and native-confirmed during convergence; the subsequent targeted third pass found no further distinct source-complete path. This is bounded convergence over the inspected scope, not a claim that the optimizer has no remaining bugs.
