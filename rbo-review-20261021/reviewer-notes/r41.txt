Native-confirmed valid-query rejection; source cause traced independently:

Window translation loses the receiver of nested member expressions.
Priority: P2 native-confirmed valid-query rejection. Wrong-value impact from same-named top-level fields is source-inferred and was not observed; do not present it as a native result.
Locations: ydb/core/kqp/opt/rbo/kqp_rewrite_select.cpp:1153-1154 and1253-1258 (ResolveWindowKeyColumn / ProcessWindowCalls).
ResolveWindowKeyColumn accepts any Member node and returns only its final field name. ProcessWindowCalls does the same for every window argument. Neither checks that the Member receiver is the row argument. Consequently, a nested field used as a window argument, partition key, or ordering key is rebound to a top-level field of the same name, or fails binding when no such field exists. This is a distinct translation path from C14 ordinary aggregate input deduplication at1034/1067, although both need full member-path preservation.
Fix: use the direct-field fast path only when the receiver is the lambda row argument. Materialize all other member expressions using their full expression trees, just like other computed window arguments and keys.
Verification basis: both importer functions and their consumers were traced; window definitions contain only the reduced field name after these fast paths. Root native feedback: nested_window_member fails in new RBO at opt/kqp_type_ann.cpp:3467, while legacy succeeds. This verifies a valid-query rejection, not a wrong-value output.
