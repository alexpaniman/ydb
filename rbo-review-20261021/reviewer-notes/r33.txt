Review r33: physical join builder and scalar strict casts
Read-only two-pass review; no repository edits or builds. No exact reproduction inputs are recorded.

CORRECTNESS

1. P1, source-confirmed: scalar Grace fallback silently discards residual ON conditions.
   Human description: A Full join with an equi key and an additional ON condition can match rows that fail the ON condition when block joins are globally enabled. Both wrong matches and missing null-extended rows result. The same failure mechanism affects joins whose complex key type disables blocks only during physical lowering.
   Root cause: rules/inline_join_filters.cpp:68 leaves residual filters inside any nonlookup equi join based on the global UseBlockHashJoin setting. rules/assign_stages.cpp:42-44 disables blocks for Full. physical_conversion/kqp_rbo_physical_join_builder.cpp:742-743 also disables blocks for List/Dict/Variant-containing keys, but only after the inlining stage. The sole remaining residual-filter guard at :557-558 applies to MapJoin; BuildGraceJoin at :502-532 has no filter operand and never consumes JoinFilters.
   Reachability challenged: kqp_rewrite_select.cpp:1970-2000 constructs Full JoinFilters; kqp_plan_conversion_utils.cpp:563-568 imports them; kqp_rbo_type_ann.cpp:500-519 accepts filters and Full typing; rules/push_simple_join_filter.cpp:24 leaves Full untouched. kqp_rbo_transformer.cpp:743-750 runs late inlining before stage assignment at :758. Global block=true, force-inlining=false, Grace Full therefore reaches the dropping builder. Cross-side non-equality predicates cannot be extracted as extra join keys or pushed to an input.
   Fix direction: decide actual join capability before filter inlining, preserve residuals in every physical fallback, and assert that no unimplemented residual predicate reaches a core. Full residuals need a semantics-preserving implementation, not a post-join WHERE filter.
   Verification: two independent source passes and source-contract assertions. Root subsequently reports native confirmation: new RBO emitted a matched row for an equal-key pair that fails the residual ON condition, where outer-join semantics require two unmatched rows. Legacy rejects that query shape, so this is a supported-by-new-RBO wrong-results defect, not an established legacy regression. Root is adding a model-based expected-row-count oracle.

2. P2, source-confirmed configuration gap: structural key casts fail without full physical peephole.
   Human description: Valid joins whose tuple/struct/list/tagged or PostgreSQL key requires normalization can fail compilation when EnableNewRBOPhysicalStagePeephole is disabled. Scalar-only compatibility lowering rejects casts emitted by the join builder itself.
   Sources: physical_conversion/kqp_rbo_physical_join_builder.cpp:267-292 selects JoinDryKeyType/JoinCommonDryKeyType for arbitrary key types; :193 emits StrictCast. yql/essentials/core/yql_expr_type_annotation.cpp:1448-1486 recursively removes structural key optionality. physical_conversion/kqp_rbo_physical_query_builder.cpp:139-140 selects focused compatibility lowering when the switch is false; physical_conversion/kqp_rbo_compatibility.cpp:371-372 dispatches every surviving StrictCast to physical_conversion/kqp_rbo_physical_strict_cast.cpp:193-197, which permits Data and Optional<Data> only.
   Important rejected false positive: duplicate same-type complex keys alone are safe; CastWrapper at yql/essentials/core/type_ann/type_ann_core.cpp:5834 removes identity casts during annotation before focused lowering. A genuine type/nullability conversion is necessary.
   Fix direction: support the structural casts generated by physical join normalization, or perform the equivalent targeted lowering before invoking the scalar-only expander.
   Verification: source-traced, not native-tested in this agent. The full-peephole path already contains the structural cast expansion routines.

CANDIDATES REQUIRING NATIVE/REACHABILITY CONFIRMATION

A. Native EqualNulls must distinguish cast failures from original NULLs.
   Left-family joins choose the preserved-side type at join builder:270-274. StrictCast of a wider non-NULL key can fail to NULL; EqualNulls is emitted for that normalized key at :454-463, potentially producing false NULL matches. Initially native EqualNulls keys are domain copies with identical types, and ordinary SQL null-safe predicates are not extracted as EqualNulls keys (kqp_expression.cpp:58-68 recognizes == and PostgreSQL = only). Mixed domains currently require another type-substitution bug such as known C06, so this is not promoted as an independent end-to-end bug.
   Independent domain-structure family to check: nested optionals or optional tuple/struct domains with nullable members. DryType strips all nested optionality, so distinct domain values can collapse to one null key before EqualNulls. Native generation occurs through MakeNullSafeJoinKeys called by scalar/simple-IN/generic-IN inlining and dependent join COUNT restoration or dual-sided pushdown. Use domain values whose distinct structural states affect correlated results, without recording their concrete representation.

B. Nonoptional structural domain keys may fail to enable NULL-safe equality.
   rules/decorrelation/dependent_join_pushdown.cpp:56-69 calls IsNullableIU (:234-239), which inspects only the top-level IsOptionalOrNull. A nonoptional tuple/struct containing optional members can therefore be considered nonnullable even though ordinary structural equality does not establish domain identity for its NULL-containing values. Requires verification through a correlated query with a structural domain.
