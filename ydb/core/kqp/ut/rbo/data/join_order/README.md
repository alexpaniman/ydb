# Native frontend join-plan parity

`KqpNativeReferenceJoinOrder` imports Pavel's TPCH/TPCDS join-order fixture,
including its queries, helper preamble, statistics, column-store schema settings,
join algorithms, and shuffle placement. All requests use `NATIVE_REQUIRED` with
both optimizer fallback switches disabled. It checks 22 TPCH and 94 TPCDS queries;
the reference exclusions are TPCDS 17/44 and the multiple-result queries 14/23/39.
The separate full compilation benchmark includes all 99 TPCDS queries.

The snapshots in this directory are copied unchanged from reference revision
`fbeb81657ef`. Thirty-one differ even from the unmodified pre-PR engine. The test
therefore defaults to `pre_pr_d11af71c6d/`, independently captured with the binary
built from `d11af71c6d026b84c3e72650813372f3ffa979c2`. Its manifest records the binary
hash, configuration, schema/statistics hashes, query hashes, expected-plan hashes,
and stale reference snapshot IDs. No expected plan was generated by the native
implementation. Canonization is deliberately rejected.

For 112 queries the expected plan comes from the original SQL on that binary.
Four queries use equivalent SQL to isolate intentional frontend normalization:

* TPCDS 29/68/73: fold arithmetic in literal `IN` elements. The old constant folder
  does not enter those expression lists; the native DAG folder does.
* TPCDS 51: remove true `IS NOT NULL` predicates on required primary-key columns,
  and give two identical window specifications a shared name. Native typing and
  binding already perform these normalizations.

These four expected plans were also produced by the pre-PR binary. Their exact
SQL changes are recorded in `*-normalization.patch`, and the unmodified legacy
plans are retained as `*.original.json`. The native test always compiles the
original query text. This keeps optimizer-policy checks separate from the
documented frontend representation differences; it does not waive plan checks.

Use `JOIN_ORDER_QUERIES=8,38,85` to select query IDs and
`JOIN_ORDER_ORACLE=reference` to compare against the unchanged original snapshots.
`JOIN_ORDER_STATISTICS=small` requires the corresponding original small-scale
statistics and snapshots; missing inputs fail explicitly. Full plans and the
compared join/shuffle trees are written to the test output directory.
