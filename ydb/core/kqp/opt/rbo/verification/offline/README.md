# Offline verifier development

Use saved snapshots with the current Python source. These commands do not run
`ya`, start YDB, capture an optimizer plan, install dependencies, or download a
solver. An existing Z3 executable is required for proof runs.

From the repository root:

```bash
export PYTHONPATH="$PWD/ydb/core/kqp/opt/rbo/verification"
export PYTHONDONTWRITEBYTECODE=1
python3 -m offline --help
```

## Import once

Choose a persistent corpus directory. An import copies the exact snapshot
bytes, attachments and explicit provenance into it. Unsupported snapshot
operators are preserved without invoking the current semantic parser, allowing
new Python support to consume the same export later. Each artifact and case
manifest is hashed. Reusing a case ID or overwriting a run is rejected.

Write `provenance.json` with the origin of the actual files, for example:

```json
{
  "export_kind": "unknown",
  "description": "Saved pair; original native source/binary identity unavailable"
}
```

Use `export_kind: "synthetic"` for hand-written or mutated fixtures. A `native`
origin requires a full 40-character `source_revision` and a 64-character
`capture_binary_sha256`. Record query settings, schema identity and any adapter
source/receipt hashes alongside them. These are caller-supplied provenance,
not attestations generated by this package. The current Git HEAD is never
substituted for a missing capture revision.

```bash
python3 -m offline import --corpus /persistent/rbo-corpus --id tpch-q3 \
  --before /captures/q3.initial.json --after /captures/q3.final.json \
  --provenance provenance.json \
  --attachment query=/captures/q3.yql --attachment schema=/captures/schema.yql

python3 -m offline check /persistent/rbo-corpus
```

The default `--scope endpoint` compares logical Initial with pre-physical Final.
Use `--scope prefix` for Initial versus a transformation prefix. Comparing two
transformation boundaries requires `--scope pair --observation initial.json`;
that original snapshot anchors bag/sequence observability. A diagnostic pair is
not relabeled as a whole-query optimizer proof.

For multiple buffered results, pass `--scope bundle --bundle bundle.json`
instead of `--before/--after`. The import preserves the original manifest,
copies each referenced snapshot and writes a portable manifest retaining client
slot order. Only a joint bundle proof counts; it does not sum independent
per-result successes. Bundle source paths must be relative, confined to their
directory, nonsymlink files. Imported artifact paths are also confined.

Inputs are limited to 64 MiB per file; the corpus manifest is limited to 16 MiB.
Malformed JSON, duplicate keys, missing files, path escapes and changed hashes
are rejected. `check` establishes byte integrity, not semantic support or proof.

## Iterate without native builds

```bash
python3 -m offline run /persistent/rbo-corpus \
  --output /persistent/rbo-runs/baseline --solver /existing/path/z3 \
  --case tpch-q3

# Edit Python encodings or admission, then run against exactly the same exports.
python3 -m offline run /persistent/rbo-corpus \
  --output /persistent/rbo-runs/candidate --solver /existing/path/z3 \
  --case tpch-q3

python3 -m offline compare \
  /persistent/rbo-runs/baseline /persistent/rbo-runs/candidate
```

Omit `--case` to run all cases, or repeat it for a selected set. To compare two
checkouts, use `--verifier-root /checkout/ydb/core/kqp/opt/rbo/verification`.
The child runs `python3 -m rbo_verifier` directly from that source root. The
identity hashes all Python source in `rbo_verifier`, `native_adapter` and this
offline package, including dirty edits, and records the Python and solver
identities. Native-to-semantic conversions should also retain their conversion
receipt in the imported provenance or attachments: replay cannot reconstruct
information missing from the export.

The runner is Linux-only and strictly serial. Default per-case limits are:

- one CPU, one verifier process and its solver descendants;
- 1 GiB per-process data allocation, 2 GiB address space;
- 2 GiB aggregate process-tree RSS cutoff, sampled every 50 ms;
- 16 GiB host available-memory reserve;
- 120 seconds construction, 10 seconds solver, 150 seconds total wall time;
- 64 MiB per output file and 1 MiB for the JSON verdict protocol.

Inherited tighter process limits are retained and recorded. The aggregate and
host-memory cutoffs are sampled guards, not kernel cgroup limits. No memory
setting may exceed 4 GiB. `--emit-smt` optionally retains the canonical formula;
it costs construction time and disk and is off by default. Use `--help` for
individual limits. Raising row bounds is an explicit experiment, not the normal
loop. Interruptions kill the owned process tree and leave no completion marker.

Each case retains stdout, stderr, command and `receipt.json`, including input
hashes, scope, source/solver identity, bounds, requested/effective limits, verdict,
elapsed time and sampled peak tree RSS. Snapshots, source files and solver are
rechecked around execution. A mutation invalidates the result. Unexpected exits
or protocol mismatches become `INFRA_ERROR`; guard cutoffs become `UNKNOWN`.
`UNSUPPORTED`, `UNKNOWN`, errors and candidates never count as proofs.

`summary.json` is written only after every selected case has a receipt. Compare
requires complete runs with identical case identities, bounds, requested
resource budgets, formula-emission setting, solver and Python identity. Source
code may differ, which is the purpose of the comparison. It reports changed
verdicts and timings and separately identifies host/effective-limit differences;
single measurements do not establish a stable speedup. Native runtime replay
and fresh-main attribution remain separate validation steps.

## Fast tests

The workflow tests exercise import integrity, joint-result packaging, strict
subprocess verdicts, source changes and comparison contracts. They use tiny,
explicitly synthetic verifier processes and need no solver or native binary:

```bash
python3 -m unittest discover \
  -s ydb/core/kqp/opt/rbo/verification/offline/tests -v 2>&1 | tail -n 60
```

The existing semantic unit tests remain the place to test actual operator
behavior. A saved JSON pair is reusable only for information it contains; new
native operator fields still require a capture/export change and later native
validation.
